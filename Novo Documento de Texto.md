Personas — Sistema Web de Vendas de Laços para Rodeio
Objetivo do MVP: desenvolver um sistema web integrado à jornada de vendas pelo WhatsApp, permitindo que o cliente personalize seu pedido de laços, escolha modelos, pesos, espessuras, cores e adicionais, além de facilitar as etapas de pagamento e envio.

As três personas representam diferentes pontos de contato com o negócio: o vendedor, o comprador individual e o comprador recorrente que realiza pedidos em maior quantidade.

Observação: como o projeto é de vendas de produtos, interpretei a dor relacionada a “agendamento” como a dificuldade na jornada de compra, configuração e acompanhamento dos pedidos.

Geneir precisa atender cada cliente individualmente pelo WhatsApp. Para montar um pedido, precisa perguntar repetidamente qual modelo de laço o cliente deseja, quantidade, peso, espessura, cor e outros adicionais.

Depois de definir o produto, ainda precisa conversar sobre valores, formas de pagamento, endereço e envio.

Esse processo consome muito tempo, dificulta o atendimento simultâneo de vários clientes e aumenta a possibilidade de erros nos pedidos.

Geneir divulga seus laços nas redes sociais e disponibiliza um link do sistema no WhatsApp.

O cliente acessa o catálogo, escolhe os modelos, personaliza as características de cada laço e finaliza o pedido.

Geneir recebe um pedido organizado, com todas as especificações, quantidade e informações necessárias para dar continuidade ao pagamento e envio.

Métrica de sucesso:

Reduzir em pelo menos 60% o tempo gasto no atendimento individual para montar pedidos.

agora liste suas dores em ordem
Olha, colocando em ordem do que mais me incomoda para o que menos me incomoda, minhas principais dores são:

1. Atendimento repetitivo: preciso fazer as mesmas perguntas para cada cliente sobre modelo, peso, espessura, cor, quantidade e adicionais.

2. Falta de tempo: perco muito tempo montando pedidos manualmente e poderia estar produzindo ou cuidando de outras partes do negócio.

3. Desorganização dos pedidos: como recebo tudo pelo WhatsApp, às vezes preciso voltar várias mensagens para conferir as escolhas de cada cliente.

4. Risco de erros: posso esquecer algum detalhe ou registrar incorretamente as especificações de um laço.

5. Demora no fechamento da venda: depois de definir o produto, ainda preciso passar valores, combinar pagamento e solicitar os dados de envio.

6. Dificuldade em atender vários clientes simultaneamente: quando chegam muitas mensagens, não consigo dar atenção a todos na mesma velocidade.

7. Falta de automatização: não tenho um sistema que conduza o cliente desde a escolha do produto até o pagamento e envio.

8. Dependência de mim para tudo: praticamente todas as etapas da venda precisam da minha intervenção.

Se eu pudesse resolver apenas uma coisa hoje, seria automatizar a montagem dos pedidos, deixando o cliente escolher tudo sozinho e me enviando o pedido pronto pelo WhatsApp.

Histórias de Usuário — Sistema de Vendas de Laços
As histórias foram elaboradas com base na entrevista com Geneir e nos requisitos funcionais definidos anteriormente.

Cada história possui critérios de aceitação (ACs) e prioridade MoSCoW.

HU01 — Visualizar e personalizar laços
Must Have — Obrigatório
História de usuário:

Como cliente, quero visualizar o catálogo de laços e escolher modelo, peso, espessura, cor e adicionais, para montar um produto de acordo com minhas preferências.

Critérios de aceitação (ACs):

AC01: O sistema deve apresentar os modelos de laços disponíveis com fotos e descrições.

AC02: Ao selecionar um modelo, o sistema deve apresentar as opções de peso, espessura, cor e adicionais disponíveis para aquele produto.

AC03: O sistema deve permitir que o cliente selecione as características desejadas antes de adicionar o produto ao carrinho.

AC04: O sistema deve impedir que o cliente adicione um produto sem preencher as opções obrigatórias.

HU02 — Montar carrinho e calcular pedido
Must Have — Obrigatório
História de usuário:

Como cliente, quero adicionar diferentes modelos de laços ao carrinho e visualizar o valor total da compra, para conferir meu pedido antes de finalizar.

Critérios de aceitação (ACs):

AC01: O sistema deve permitir adicionar diferentes modelos de laços ao carrinho.

AC02: O sistema deve permitir alterar a quantidade de cada produto.

AC03: O sistema deve calcular automaticamente o subtotal de cada item e o valor total do pedido.

AC04: O sistema deve permitir remover produtos do carrinho.

AC05: O sistema deve apresentar um resumo contendo modelos, características, quantidades e valores.

HU03 — Finalizar pedido pelo WhatsApp
Must Have — Obrigatório
História de usuário:

Como cliente, quero informar meus dados e encaminhar meu pedido completo pelo WhatsApp, para facilitar a comunicação com o vendedor e dar continuidade à compra.

Critérios de aceitação (ACs):

AC01: O sistema deve solicitar nome, telefone e endereço de entrega do cliente.

AC02: O sistema deve apresentar uma revisão dos produtos e dos dados informados antes da confirmação.

AC03: Após a confirmação, o sistema deve gerar uma mensagem organizada contendo os produtos, características, quantidades e valor total.

AC04: O sistema deve disponibilizar um direcionamento para o WhatsApp do vendedor com as informações do pedido.

AC05: O sistema deve permitir que o cliente retorne ao pedido para corrigir informações antes de encaminhá-lo.

Por que as três são Must Have?

Porque uma depende da outra para entregar a proposta principal do MVP:

O cliente escolhe e personaliza o laço.

O cliente monta seu pedido e confere os valores.

O cliente encaminha o pedido organizado para Geneir.

Sem qualquer uma dessas etapas, o sistema não resolveria completamente o problema identificado na entrevista.

Sugestão para uma próxima versão: adicionar pagamento integrado, acompanhamento de pedidos, cálculo automático de frete e painel administrativo para Geneir gerenciar modelos, preços e disponibilidade. Essas funcionalidades podem ser avaliadas como Should Have ou Could Have, conforme as necessidades descobertas durante os testes do MVP.
